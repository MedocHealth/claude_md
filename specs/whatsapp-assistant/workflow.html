Rules the model never decides

  1. Whether a tool is a read or a write — the catalogue's kind.
  2. Whether the user may call a tool — permission gate runs before any HTTP; the model only ever sees permitted tools.
  3. hospitalId — stripped from model output, injected from the verified session.
  4. Whether a write executes — only on the Confirm button or a typed confirm, within 10 minutes, exactly once.
  5. Which document chunks are searchable — the permission filter sits inside $vectorSearch.
  6. Whether a bot-initiated message may be free text (24-hour window open) or must be an approved template.
  7. Vitals, quantity and date range validation.
  8. Masking of patient contact fields.
  9. Rate limits, daily LLM caps, pause state.
  10. Which category a document may be filed into — uploader's modules ∩ category mapping.
Global commands, any state

menu · help · cancel · confirm / haan · switch · language · status · pause / resume · unlink · privacy · a number 1–9 picks the last button or row.

Interruption rules
  1. A new intent while a write is pending is answered; the pending action survives with a one-line reminder (MSG-W07).
  2. Pending actions expire after 10 minutes (MSG-W04). Only one pending action at a time (MSG-W08).
  3. Clarification questions time out silently after 30 minutes.
  4. Switching hospital cancels a pending action minted for the other tenant (MSG-W09).
  5. Revoked or disabled numbers get one refusal per 24 hours, then silence.

Fixed system strings shipped as messages.en.json / messages.hi.json. Free-form answers (patient cards, lists, document answers) are model-generated within the format rules and shapes shown in the flows.
